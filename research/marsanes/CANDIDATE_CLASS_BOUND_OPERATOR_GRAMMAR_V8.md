# Candidate v8 — Class-Bound Operator Grammar

Status: CANDIDATE, not final model.

## Core finding

Marsanes does not currently support a simple mapping:

LETTER -> ONTOLOGICAL CLASS.

Instead, independently named textual classes are associated with different FORMAL OPERATIONS.

## Candidate mapping

SELF_BEGOTTEN
-> SERIES7(simple vowels)

SECOND_SCHEMA
-> SERIES5 + TWO_SOUND / DIPHTHONG-LINK

MALE_THIRD_SHAPE
-> REPEAT3(simple vowels)

ANGELIC_NOMENCLATURE
-> COMBINE(consonant,vowel) + SUBSTITUTE_VOWEL(frame)

HIDDEN_GODS_SUBMISSION
-> CHANGE(form) + PERFORMANCE{BEAT,PITCH,SILENCE,IMPULSE}

## Important distinction

This is stronger than a fixed substitution cipher but weaker than an access-token theory.

Current evidence supports:
CLASS -> OPERATOR BUNDLE.

It does not yet establish:
BOUNDARY_i -> TOKEN_i -> AUTHORIZATION_i.

## Why this matters esoterically

If the text assigns different transformations to different soul/divine classes, then the sacred form is potentially GENERATED by rule rather than merely looked up in a correspondence table.

That would make Marsanes a candidate formal grammar of sacred representation.

## Falsifier

The model fails if:
- critical-edition verification removes the class/operator links;
- the same mappings are completely explained by ordinary grammar-school exercise conventions;
- operator bundles do not transfer to independently labeled functions in another text;
- results require restored material rather than secure text.
