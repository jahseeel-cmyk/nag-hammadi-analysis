# Marsanes X30 vs X31 Mechanism Discrimination Test v18 — PREREGISTRATION

Freeze date: 2026-09-21

## Research question

Why does Marsanes X30:15–22 use an explicit performance bundle
(beat / pitch / silence / hormē)
while X31:19–X32:5 generates explicit consonant-vowel strings without that bundle?

The aim is to discriminate among competing LOCAL mechanisms.

## Target A — X30:12–22

Core secure sequence:
- altered/diverse consonantal forms
- relation to hidden gods
- beat / pitch / silence / hormē
- summon the semivowels
- all are hypotassein
- one sound

## Target B — X31:19–X32:5

Core secure sequence:
- bring together similar elements
- voiced elements / consonants
- generated syllabic strings:
  bagadazatha, begedezethe, etc.
- separation from angels
- no explicit beat / pitch / silence / hormē

## Competing hypotheses

### H18-A — SEMIVOWEL ACTIVATION
Performance is required specifically when semivowels are ACTIVATED/SUMMONED.

Predictions:
A1. X30 explicitly contains semivowel summoning.
A2. X31 generation does not require semivowel summoning as an operation.
A3. Mere taxonomic mention of semivowels elsewhere does NOT trigger performance.
A4. Performance should be absent in ordinary CV generation.

Failure:
secure performance occurs with no semivowel activation, or X31 contains equivalent semivowel activation without performance.

### H18-B — MANY-TO-ONE UNIFICATION
Performance is required when multiple phonetic elements are reduced/ordered into ONE SOUND.

Predictions:
B1. X30 explicitly culminates in one sound.
B2. X31 generates a plurality of distinct syllabic outputs rather than one sound.
B3. Taxonomic/combinatory passages without many-to-one reduction lack performance.
B4. Performance phrase syntactically governs the one-sound process.

Failure:
another many-to-one phonetic reduction lacks performance, or X30 one-sound clause is independent.

### H18-C — HIDDEN / UNREPRESENTED POWER RELATION
Performance is required because altered sounds interface with hidden gods or hidden/unwritten phonetic entities.

Predictions:
C1. X30 uniquely includes hidden gods adjacent to performance.
C2. X31 ordinary CV generation lacks hidden-power relation.
C3. the performance bundle should attach syntactically or conceptually to the hidden-power relation, not merely to the semivowel clause.

Failure:
forward syntax strongly separates performance from hidden-god clause, or hidden-power relation appears elsewhere without execution.

### H18-D — GENERIC SACRED-NAMING INTENSITY
Performance is required whenever the text is engaged in especially sacred divine/angelic nomenclature.

Predictions:
D1. performance should co-occur with nomenclature.
D2. comparably sacred naming passages should show equivalent execution vocabulary.

Failure:
X31 and neighboring nomenclature passages are equally sacred but lack performance.

### H18-E — GENERAL COMPLEXITY / RHETORICAL EMPHASIS
Performance terms mark unusually complex grammatical material or rhetorical emphasis rather than a specific phonetic operation.

Predictions:
E1. X30 should be objectively more structurally complex than X31.
E2. other highly complex combinatory passages should also attract execution vocabulary.

Failure:
X31 is equally/more combinatorially complex but lacks performance.

T18-8 NEGATIVE SEMIVOWEL CONTROL
Do neighboring semivowel-classification passages lack performance when semivowels are only classified rather than summoned?

## Scoring

For each hypothesis:
- +1 for each preregistered prediction supported
- 0 for indeterminate
- -1 for contradicted

No weights may be changed after scoring begins.

A hypothesis is:
STRONGLY FAVORED if score >= +3 with no contradiction.
SUPPORTED if score >= +2.
MIXED if score between -1 and +1.
DISFAVORED if score <= -2.

This score is a transparent discrimination device, not a probability.

## Anti-fitting rules

Do not:
- redefine semivowel after seeing result;
- count simple mention as activation;
- treat any plural-to-singular wording as phonetic unification unless sound is explicit;
- infer ritual intensity from modern esoteric expectations;
- use restoration-dependent wording as secure;
- import PGM/Hekhalot functions into the local Marsanes syntax.

If H18-C wins, return to hidden-power interface model.

If H18-D or H18-E wins, downgrade v17 phonetic-transition interpretation.
